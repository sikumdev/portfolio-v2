원인개선안
01 · 답은 이미 FAQ에 있다자주 오는 문의 다수는 FAQ에 안내글이 있지만, 사용자가 찾지 않고 전화한다.근거: 반복 문의 —는 FAQ나 매뉴얼에 이미 안내가 있었고, 빈도 '상' 유형도 —가 마찬가지였습니다. 문의 원인 분석 문서에도 안내글이 "거의 조회되지 않았고, 모르면 전화하는 게 더 편해서" 전화한다는 기록이 있습니다.
오류 메시지에 해결 방법 연결실행오류가 뜬 그 자리에서 해결 방법으로 연결. 예) 구형 구성요소 지원 종료, PDF 생성 오류 안내에 해결 방법 링크 추가, 전자서명 인증 실패 문구에 "허용된 접속 환경에서 다시 시도" 안내 추가. 반복 문의 약 10% 이상 감소
프로그램 안에 FAQ 버튼제안 · 보류의뢰구분·양식별로 해당 안내글에 바로 연결. 개발 리소스 문제로 보류되어, 위의 오류 메시지 개선으로 먼저 우회
FAQ 게시판 재구성제안빈도 '상' 유형부터 안내글 추가, 업무구분별 정리
02 · 의뢰처마다 절차가 다르다자동연계 건의 변경·수정 절차가 의뢰처 A·B·C마다 달라 회원사가 알기 어렵고, 의뢰처 쪽 처리 미숙으로 생기는 문의도 많다.근거: 의뢰처 관련 문의가 전체의 —, 반복 문의 유형의 —가 의뢰처·자동연계 관련. 문의 원인 분석 문서에서 "연계 의뢰가 안 들어온다", "발송 후 의뢰처에서 안 보인다"는 문의는 대부분 의뢰처 담당자의 처리 미숙이 원인으로 확인됐습니다.
의뢰처별 절차 한 장 정리제안변경·수정·반송·취하 절차를 회원사와 의뢰처가 같이 참고
연계 상태 확인 창 단순화제안숨은 메뉴의 칸 개수 대신 "의뢰처 수신 / 미수신"을 크게 표시해, 발송 문제인지 의뢰처 처리 문제인지 바로 구분
03 · 의뢰처 A 업무는 매뉴얼이 없다업무구분이 시스템 A로 잡힌 문의에도 의뢰처 A 업무가 섞여 있어, 실제 관련 문의는 매달 100건 안팎이다.근거: 시스템 A로 분류된 문의의 월별 세부 내용을 확인한 결과, 의뢰처 A 업무가 섞여 있어 이를 합치면 대략 매달 100건으로 추정했습니다(집계상 의뢰처 A만은 월평균 —건). 의뢰처 A 업무는 프로그램 사용법과 처리 절차를 안내하는 매뉴얼이 따로 없었습니다.
의뢰처 A 업무 매뉴얼제안프로그램 사용법과 연계 상태 확인 절차
